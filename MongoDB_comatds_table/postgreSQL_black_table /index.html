PostgreSQL Commands List

Что такое PostgreSQL?

PostgreSQL — объектно-реляционная система управления базами данных (СУБД) с открытым исходным кодом. Разрабатывается с 1986 года, релиз 1.0 — в 1996. Сегодня один из самых популярных и мощных движков СУБД в мире. Поддерживает полный стандарт SQL с расширениями: ACID-транзакции, сложные типы данных (JSON, JSONB, ARRAY, UUID, ENUM), оконные функции, CTE, хранимые процедуры, полнотекстовый поиск и геопространственные данные (PostGIS).

  • vs MongoDB — строгая реляционная схема, SQL-запросы, JOIN между таблицами, гарантии ACID на уровне транзакций; MongoDB — документная NoSQL БД без фиксированной схемы
  • vs MySQL — лучшая поддержка стандарта SQL, нативные типы JSONB / ARRAY, оконные функции, CTE, расширяемая архитектура (можно добавлять типы и функции); MySQL — проще в настройке, исторически быстрее на простых read-операциях
  • vs SQLite — многопользовательский сервер, масштабируется под большие объёмы данных, предназначен для production; SQLite — встраиваемый движок в один файл, отлично для локального dev и мобильных приложений
  • vs Redis — PostgreSQL хранит данные на диске с поддержкой сложных запросов; Redis — in-memory хранилище для кэша и очередей с очень быстрым доступом по ключу

psql \commands — мета-команды интерактивной консоли

Мета-команды psql начинаются с обратного слеша \ и не являются SQL — они обрабатываются самим клиентом psql. Работают только в интерактивном режиме или внутри SQL-скриптов выполняемых через psql -f file.sql. Позволяют инспектировать схему БД, управлять выводом, выполнять внешние файлы и оболочечные команды.

\l — базы данных
\dt — таблицы
\d table — структура
\du — роли
\di — индексы
\dn — схемы
\timing — замер времени
\x — вертикальный вывод
\copy — CSV импорт/экспорт
\? — справка мета-команд
\h CMD — справка SQL
\q — выйти

DB Management — управление базами данных

Раздел охватывает операции уровня сервера PostgreSQL: создание и удаление баз данных, управление ролями и правами доступа, организацию схем, транзакции, представления (VIEW / MATERIALIZED VIEW), резервное копирование через pg_dump, анализ производительности через EXPLAIN ANALYZE, обслуживание таблиц через VACUUM, и мониторинг через системные представления pg_stat_*.

Эти команды — фундамент работы DBA и backend-разработчика в production. Хорошее понимание этого слоя позволяет диагностировать проблемы производительности, безопасно управлять доступом и поддерживать работоспособность базы под нагрузкой.

Что такое миграции (Migrations)?

Миграция — это версионированное изменение схемы базы данных, оформленное в виде файла с кодом. Каждая миграция имеет два метода: UP — применяет изменение (добавить таблицу, колонку, индекс), и DOWN — откатывает его обратно. Инструменты вроде Sequelize, Prisma, Knex автоматически отслеживают список применённых миграций в специальной служебной таблице в самой БД (SequelizeMeta, _prisma_migrations).

Зачем это нужно: синхронизация схемы БД между всей командой, staging и production окружениями. Без миграций каждый разработчик вручную правит схему — это ведёт к рассинхрону. Миграции — это «git для схемы базы данных».

→
2 Закоммитить файл в git
→
3 Запустить на сервере (db:migrate)
→
4 Rollback если нужно (undo)
